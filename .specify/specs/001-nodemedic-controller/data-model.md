# Phase 1 Data Model — NodeMedic Controller

**Plan**: [`plan.md`](./plan.md) · **Spec**: [`spec.md`](./spec.md) · **Date**: 2026-06-12

This document captures the entities the controller reads, writes, and reasons about. The cross-scope CRD schema lives in [`contracts/nhd-crd.yaml`](./contracts/nhd-crd.yaml); this document is the **controller's model of those entities**, plus the small set of internal types the controller owns.

Everything below maps 1:1 to a Go file in `internal/` or `api/` per the `plan.md` repo layout.

---

## 1. External entity: `NodeHealthDiagnosisAI` (NHD)

**Owner**: Scope 3 (Constitution Article II.2). The controller treats this as read-mostly, with two write surfaces: `spec.*` on creation, and `status.action.*` + `status.phase` + `status.conditions[]` after diagnosis.

**Source**: [`contracts/nhd-crd.yaml`](./contracts/nhd-crd.yaml) — vendored from `nodemedic-scope.md` §2.2; frozen at `v1alpha1`.

**Go type location**: `api/v1alpha1/nodehealthdiagnosisai_types.go` (generated by `controller-gen`).

### 1.1 Fields the controller writes

| Path | When | Validation |
|---|---|---|
| `spec.case.caseId` | On `Create` | UUIDv4, generated by controller |
| `spec.case.nodeName` | On `Create` | matches the trigger Node.metadata.name; ≤253 chars |
| `spec.case.clusterName` | On `Create` | from `--cluster-name` flag; non-empty; MUST start with `test-` (Constitution I.9) |
| `spec.case.provider` | On `Create` | enum `aws | azure`; resolved per FR-2 |
| `spec.case.region` | On `Create` | non-empty; from `topology.kubernetes.io/region` |
| `spec.case.instanceId` | On `Create` | non-empty; from `spec.providerID` parser |
| `spec.case.trigger.{type,reason,message,observedAt}` | On `Create` | trigger payload from the watched NodeCondition |
| `spec.budgets.maxTurns` | On `Create` | default `15`; integer |
| `spec.budgets.maxBudgetUSD` | On `Create` | default `"0.50"`; decimal-as-string |
| `spec.budgets.deadline` | On `Create` | RFC3339; `observedAt + 60s` |
| `status.phase` | On `Create` and on each transition | enum |
| `status.conditions[]` | On every phase transition | standard k8s Condition with `lastTransitionTime` and `reason` |
| `status.action.decision` | On gate evaluation | enum `Applied | HumanInLoop | Skipped` |
| `status.action.operation` | On gate evaluation | enum `cordon | noop` |
| `status.action.appliedAt` | On gate `Applied` | RFC3339, set after successful Node patch |
| `status.action.notifications.slack.{channel,ts,permalink}` | On Slack post success | best-effort dedup; OK to be empty |

### 1.2 Fields the controller reads (never writes)

| Path | Used by |
|---|---|
| `status.diagnosis.confidence` | Confidence gate (FR-6) |
| `status.diagnosis.evidence[].source` | Confidence gate (FR-6) — distinct-source count |
| `status.diagnosis.recommendation.action` | Confidence gate (FR-6) |
| `status.diagnosis.rootCause` | Slack message body |
| `status.diagnosis.rcaCategory` | Slack message header |
| `status.diagnosis.auditLogRef.objectStore` | Slack "View audit log" button URL |

### 1.3 Phase state machine

```
              ┌──────────────────────────────────────┐
              │                                      │
   ""(new) ──► Pending ──► Diagnosing ──► Diagnosed ──► Acted
                              │
                              └─ DeadlineExceeded ─► Failed (terminal)
```

For v1 the `Evaluating` and `Evaluated` phases defined in `nodemedic-scope.md` §2.3 are skipped (per spec §2.G4 and §3 Non-goals). The schema retains the enum values so a future eval agent can be added without a CRD bump.

| Phase | Set by | Reconciler action |
|---|---|---|
| `""` | n/a (just created) | Treat as `Pending`; trigger FR-4 |
| `Pending` | controller (FR-3) | `POST /diagnose`; on 202 → `Diagnosing` |
| `Diagnosing` | controller (FR-4) | If `now > deadline` → FR-7 retry path. Else requeue at `min(deadline, now+10s)` |
| `Diagnosed` | agent | Run gate (FR-6). Pass → cordon, set `Acted` w/ `decision=Applied`. Fail → set `Acted` w/ `decision=HumanInLoop`. Slack either way. |
| `Acted` | controller (FR-6) | Terminal; reconciler returns without requeue |
| `Failed` | controller (FR-7) | Terminal; reconciler returns without requeue |

### 1.4 Conditions (status.conditions[])

| `type` | `status` transitions | `reason` enum | When emitted |
|---|---|---|---|
| `AgentInvoked` | False → True (after 202); True → False (on Failed) | `Posted` / `BadRequest` / `Unauthorized` / `AgentUnreachable` / `DeadlineExceeded` | After `POST /diagnose` outcome |
| `ReportReady` | False → True | `DiagnosisWritten` | When the controller observes `phase=Diagnosed` |
| `ActionApplied` | False → True | `Cordoned` / `HumanInLoop` / `Skipped` | After gate evaluation |
| `Notified` | False → True | `SlackOK` / `SlackFailed` | After Slack notify attempt(s) |

`lastTransitionTime` and a free-form `message` are set on every change (NFR-7).

### 1.5 NHD name convention

`<nodeNameTruncated50>-<unixTsSeconds>` where `unixTsSeconds` is `observedAt`'s Unix seconds. Deterministic so a duplicate flap within the debounce window collides on `Create` and short-circuits to "case already exists" (FR-3). Truncation rule: take first 50 ASCII chars of `Node.metadata.name`, replace any character outside `[a-z0-9-]` with `-`, trim trailing `-`.

## 2. External entity: `corev1.Node`

**Owner**: kube-controller-manager + cloud-controller-manager. The controller treats this as read-only **except** for `spec.unschedulable` which is the only mutation we ever apply.

### 2.1 Read paths (FR-2 metadata resolution)

| Read | Source field | Resolution rule |
|---|---|---|
| `provider` | `metadata.labels["cf.newrelic.com/cloud-provider"]` (preferred), else `spec.providerID` URI scheme | `aws://…` → `aws`, `azure://…` → `azure`. Anything else → `MetadataResolutionFailed` Event, no NHD created |
| `region` | `metadata.labels["topology.kubernetes.io/region"]` | Required. Fall back to `failure-domain.beta.kubernetes.io/region` only if GA label missing |
| `instanceId` | `spec.providerID` | AWS: regex `^aws:///[^/]+/(i-[a-z0-9]+)$` → group 1. Azure: regex `.*/virtualMachines/([^/]+)$` → group 1 |
| `clusterName` | controller flag `--cluster-name` (NOT the Node) | The Node has no reliable cluster name |

### 2.2 Read paths (FR-1 trigger detection)

`status.conditions[]` — informer watches transitions. Predicate filter:
- Type ∈ `--watched-conditions` allowlist.
- Old status ∈ {`False`, `Unknown`, missing}, new status = `True`.
- `(node, type)` not seen within the last 30 s (in-memory debounce per R-9).

### 2.3 Write path (FR-8 cordon)

| Write | Field | Method | Idempotency |
|---|---|---|---|
| Cordon | `spec.unschedulable = true` | `client.Patch(node, client.MergeFrom(orig))` | If already true, succeed without re-patching |

**Forbidden writes**: anything else on `Node`. CI grep test in the controller repo asserts no `client.Update(...node...)` or `client.Patch(...node..., ...)` against any field besides `spec.unschedulable`.

### 2.4 Refusal rule (FR-8)

Before patching, the controller asserts `node.Name == nhd.Spec.Case.NodeName`. Mismatch ⇒ refuse, emit a `WrongNodeRefused` Event on the NHD, mark `Failed`. This is the safety belt against label confusion in the trigger pipeline.

## 3. External entity: `corev1.Event`

**Owner**: kube-apiserver / event-recorder. The controller emits Events; it does not consume them in v1.

### 3.1 Events the controller emits

| Reason | InvolvedObject | When | Severity |
|---|---|---|---|
| `MetadataResolutionFailed` | `Node` | FR-2 fields can't be resolved | Warning |
| `CaseCreated` | `Node` | NHD `Create` succeeded | Normal |
| `ConditionCleared` | `Node` | Watched condition flipped True→False after `Acted` (FR-10) | Normal |
| `WrongNodeRefused` | NHD | Refusal rule §2.4 fired | Warning |
| `NotifierFailed` | NHD | Slack post failed all retries (FR-9) | Warning |
| `PhaseTransition` | NHD | every phase change (informational, paired with the Condition update) | Normal |

## 4. Internal entity: `Case` (in-process)

In-memory only; not persisted. Lives inside the reconciler for the duration of one `Reconcile(...)` call. Defined in `internal/controller/types.go`.

```go
type Case struct {
    Key        client.ObjectKey       // namespace/name of the NHD
    NHD        *v1alpha1.NodeHealthDiagnosisAI
    Node       *corev1.Node           // fetched once per reconcile, may be nil if deleted
    Now        time.Time              // injected for tests; otherwise time.Now()
    Decisions  Decisions              // populated as the function progresses
}

type Decisions struct {
    GateResult       *GateResult        // nil until phase=Diagnosed observed
    CordonResult     *CordonResult      // nil until cordon attempted
    SlackResult      *SlackResult       // nil until Slack attempted
    NextRequeueAfter time.Duration      // 0 means terminal
}
```

No fields besides the ones above; the reconciler is a small linear function over Case.

## 5. Internal entity: `GateResult`

Output of the pure confidence-gate function (`internal/controller/confidence_gate.go`).

```go
type GateOutcome int
const (
    GatePass GateOutcome = iota
    GateFail
    GateSkip          // recommendation.action == NoAction
)

type GateResult struct {
    Outcome           GateOutcome
    Confidence        float64
    DistinctSources   int
    SourcesByName     []string          // sorted, deduped
    RecommendedAction string            // verbatim from NHD
    Reason            string            // human-readable, goes into Condition.message
}
```

Decision matrix (FR-6, Constitution Article I.3):

| Confidence | Distinct sources | Recommended action | Outcome | Cordon? |
|---|---|---|---|---|
| ≥ `--min-confidence` (default 0.7) | ≥ `--min-evidence-sources` (default 2) | `Cordon` ∨ `DrainAndCordon` | `GatePass` | YES |
| any | any | `NoAction` | `GateSkip` | NO (treat as HumanInLoop framing) |
| < threshold OR < sources OR action ∉ allowlist | — | `GateFail` | NO (HumanInLoop) | |

`DrainAndCordon` from the agent is treated as `Cordon` (the controller never drains; FR-8). The Slack message reflects what was *requested* and what was *applied* separately.

## 6. Internal entity: `DebounceMap`

`internal/controller/debounce.go`. Wraps a `sync.Map` keyed by `debounceKey`.

```go
type debounceKey struct {
    Node string
    Type string  // NodeCondition.type
}

type DebounceMap struct {
    window time.Duration
    last   sync.Map  // map[debounceKey]time.Time
}

func (d *DebounceMap) Allow(k debounceKey, now time.Time) bool {
    prev, ok := d.last.Load(k)
    if ok && now.Sub(prev.(time.Time)) < d.window {
        return false
    }
    d.last.Store(k, now)
    return true
}
```

Window default: 30 s (FR-1). Settable via `--debounce-window` flag.

## 7. Internal entity: agent HTTP request/response

Mirror of [`contracts/post-diagnose.md`](./contracts/post-diagnose.md). Lives in `internal/agentclient/types.go`. Golden-tested so the contract is locked.

## 8. Internal entity: Slack message envelope

`internal/notifier/messages.go`. Three constructors (Block Kit JSON):

| Function | Used by | Header | Severity styling |
|---|---|---|---|
| `BuildApplied(...)` | Gate pass + cordon ok | `NodeMedic: <node> – <rcaCategory> (conf <X>)` | green/info |
| `BuildHumanInLoop(...)` | Gate fail | `NodeMedic: <node> – needs human review (conf <X>)` | red/critical framing |
| `BuildCritical(...)` | FR-7 terminal failure | `NodeMedic: <node> – AGENT FAILED` | red/critical, includes `reason` |

Each builds the same outer shape: `header → fields(cluster, action) → section(rca) → context(kubectl command)`. No external links in v1 (R-6).

## 9. Field-by-field validation summary (controller-side)

| Field | Validator | Failure handling |
|---|---|---|
| `spec.case.caseId` | UUIDv4 regex | drop trigger, log error |
| `spec.case.provider` | enum check | `MetadataResolutionFailed` Event |
| `spec.case.{region,instanceId}` | non-empty | `MetadataResolutionFailed` Event |
| `spec.case.clusterName` | non-empty + starts with `test-` | controller fails to start (Helm chart guard) |
| `spec.case.trigger.observedAt` | RFC3339 parse | drop trigger |
| `spec.budgets.deadline` | RFC3339; > observedAt | drop trigger |
| `status.diagnosis.confidence` | parseable float in [0.0, 1.0] | gate fail with reason `MalformedConfidence` |
| `status.diagnosis.evidence[].source` | enum `{nrql, ssh, kubectl, cloud, proc, log}` | unknown source counted as 1 distinct (lenient) but logged WARN |
| `status.diagnosis.recommendation.action` | enum `{Cordon, DrainAndCordon, NoAction}` | unknown → gate fail with reason `UnknownAction` |

CRD-level validation (OpenAPI schema rules, written in `contracts/nhd-crd.yaml`) catches most of these at apiserver-admission time. The controller-side checks above are a defense-in-depth layer for cases where the CRD validation is loosened during local dev.
