**Two contracts cross scope boundaries** — define them once, both sides code against them:

1. `NodeHealthDiagnosisAI` **CRD** — written by Scope 3, read by Scope 2.
2. `POST /diagnose` **HTTP contract** — called by Scope 2, served by Scope 3.

These are specified in §2 and §3 below. Everything else is internal to one scope.

## 2. Shared API: `NodeHealthDiagnosisAI` CRD

One CR per diagnosis case. Created by the **agent** (Scope 3) when it finishes. Read by the **controller** (Scope 2) to drive cordon + notify.

### 2.1 GroupVersionKind
- **Group:** `nodemedic.cf.newrelic.com`
- **Version:** `v1alpha1`
- **Kind:** `NodeHealthDiagnosisAI` · short name `nhd`
- **Scope:** Namespaced (namespace `container-fabric`). Per-cluster; no cross-cluster aggregation in v1.
- **Name convention:** `<node-short>-<unix-ts>` (e.g. `ip-10-1-2-3-1717059600`). Stable, predictable, and the controller computes the same name when reconciling so it can correlate the trigger with the eventual CR.

### 2.2 Schema (OpenAPI v3, abridged)

```yaml
spec:
  case:
    caseId:        string   # UUIDv4, generated by controller, echoed by agent
    nodeName:      string   # apiserver Node name
    clusterName:   string   # e.g. test-odd-wire | aks-cf-test-1
    provider:      string   # enum: aws | azure  — picks the Cloud-Info backend
    region:        string   # e.g. us-east-2 | eastus2
    instanceId:    string   # i-0abc… (AWS) | <vmName> (Azure)
    trigger:
      type:        string   # NodeCondition type, e.g. ConntrackSaturated
      reason:      string   # NPD rule reason
      message:     string   # NPD rule message (truncated 256B)
      observedAt:  string   # RFC3339, when NPD flipped the Condition
  budgets:
    maxTurns:      integer  # default 15
    maxBudgetUSD:  string   # decimal-as-string, default "0.50"
    deadline:      string   # RFC3339, controller-set hard wall-clock cap

status:
  phase:           string   # Pending|Diagnosing|Diagnosed|Evaluating|Evaluated|Acted|Failed
  conditions:                     # standard k8s Conditions
    - type:        string   # AgentInvoked|ReportReady|EvalApproved|ActionApplied
      status:      "True"|"False"|"Unknown"
      reason:      string
      message:     string
      lastTransitionTime: string
  diagnosis:                      # written once by Scope 3 agent
    rootCause:        string      # one-paragraph RCA
    rcaCategory:      string      # enum: Conntrack|FD|PID|Inode|Disk|DNS|IMDS|Kernel|Kubelet|Unknown
    confidence:       number      # [0.0, 1.0]
    evidence:                     # min 2 entries from distinct sources for gate to pass
      - source:      string       # nrql|ssh|kubectl|aws|proc|log
        ref:         string       # query / command / path
        result:      string       # raw result, truncated 4KB
        observedAt:  string
    recommendation:
      action:        string       # Cordon|DrainAndCordon|NoAction
      reason:        string
    auditLogRef:
      objectStore:   string       # s3://... or local path; PreToolUse hook output
    modelUsed:       string       # claude-opus-4-7 | claude-sonnet-4-6
    turnsUsed:       integer
    costUSD:         string
    completedAt:     string
  evaluation:                     # POST-HACKATHON; written by eval agent
    agreesWithDiagnosis: boolean
    confidence:       number
    notes:            string
    completedAt:      string
  action:                         # written by Scope 2 controller
    decision:         string      # Applied|Skipped|HumanInLoop
    operation:        string      # cordon|noop
    appliedAt:        string
    notifications:
      slack:        { channel: string, ts: string, permalink: string }
      pagerduty:    { incidentKey: string, dedupKey: string }
```

### 2.3 Phase state machine

```
Pending ─► Diagnosing ─► Diagnosed ─► (Evaluating ─► Evaluated)? ─► Acted
                  │            │                                       ▲
                  └─ Failed ◄──┴────────────────────────────────────── timeout/budget exceeded
```

For the **hackathon**, the Evaluating/Evaluated steps are skipped — controller transitions `Diagnosed → Acted` directly. The phase exists in the schema so the prod path doesn't need a CRD bump.

### 2.4 RBAC

| Subject | Verbs |
|---|---|
| `nodemedic-controller` (Scope 2) | `get,list,watch,update,patch` (`nhd`); `patch nodes` (cordon); `create events` |
| `nodemedic-agent` (Scope 3) | `create,get,update` (`nhd`); read-only on `nodes`, `pods`, `events` |
| `nodemedic-eval` (post-hackathon) | `get,update` status subresource only |

Status subresource is enabled on the CRD so spec/status updates are independently authorized.

## 3. Shared API: `POST /diagnose`

Controller (Scope 2) calls Agent runtime (Scope 3). Authenticated via shared secret in an in-cluster `Secret`; in-cluster service `nodemedic-agent.container-fabric.svc:8080`.

### 3.1 Request

```http
POST /diagnose HTTP/1.1
Authorization: Bearer <token>
Content-Type: application/json

{
  "caseId":      "8f3c…",            // UUIDv4 from controller
  "nodeName":    "ip-10-1-2-3.ec2.internal",
  "clusterName": "test-odd-wire",
  "provider":    "aws",              // "aws" | "azure" — picks Cloud-Info backend
  "region":      "us-east-2",        // e.g. "us-east-2" | "eastus2"
  "instanceId":  "i-0abc1234…",      // AWS instance-id or Azure VM name
  "trigger": {
    "type":      "ConntrackSaturated",
    "reason":    "ConntrackHigh",
    "message":   "nf_conntrack_count=262100 max=262144",
    "observedAt":"2026-06-12T15:00:00Z"
  },
  "budgets": { "maxTurns": 15, "maxBudgetUSD": "0.50", "deadlineSec": 60 }
}
```

### 3.2 Response — async

```http
HTTP/1.1 202 Accepted
{ "caseId": "8f3c…", "status": "queued" }
```

Result is **not** returned in the HTTP response. Agent writes the CR (`NodeHealthDiagnosisAI/<name>`) when done; controller learns about completion via informer. Choosing async keeps the controller's reconcile loop short and lets long agent runs survive controller pod restarts.

### 3.3 Errors

| Code | When | Controller behavior |
|---|---|---|
| 400 | Missing required field | Mark CR `Failed`, log, do not retry |
| 401 | Bad/missing token | Mark CR `Failed`, page on-call |
| 429 | Agent at concurrency cap | Backoff + retry (exp, max 3) |
| 5xx | Agent crash | Mark CR `Failed` after 3 retries |

### 3.4 Health & ops endpoints

`GET /healthz` (200 if process up), `GET /readyz` (200 if Anthropic + MCP backends reachable), `GET /metrics` (Prometheus: `nodemedic_agent_cases_total{outcome=...}`, `nodemedic_agent_turns_per_case`, `nodemedic_agent_cost_usd_per_case`, `nodemedic_agent_latency_seconds`).

### 4.2 Fault → plugin → injection table (binding for Scope 1)

| NodeCondition Type | Plugin script | Detection | Injection (`make inject-<x>`) |
|---|---|---|---|
| `ConntrackSaturated` | `conntrack.sh` | `count/max ≥ 0.95` | `iptables`-driven flooder + lower `nf_conntrack_max` |
| `FDExhaustion` | `fd.sh` | `/proc/sys/fs/file-nr` first column / second ≥ 0.9 | open-fd hog pod with `ulimit -n` cranked |
| `PIDExhaustion` | `pid.sh` | `/proc/sys/kernel/pid_max - /proc/loadavg` heuristic; or `/sys/fs/cgroup/pids.current` vs `pids.max` | fork-bomb pod inside its own cgroup |
| `InodeExhaustion` | `inode.sh` | `df -i` `IUse%` ≥ 95% on `/var/lib` | `seq 1 5000000 \| xargs touch /tmp/...` |
| `DiskFill` | `disk.sh` | `df` `Use%` ≥ 90% on `/var/lib` | `fallocate -l 30G /var/lib/fill` |
| `DNSPartition` | `dns.sh` | resolve `kubernetes.default.svc.cluster.local` with 2 s timeout, 3-strikes | `iptables -A OUTPUT -p udp --dport 53 -j DROP` (scoped to a netns) |
| `IMDSThrottle` | `imds.sh` | AWS: `curl -m 2 -H 'X-aws-ec2-metadata-token-ttl-seconds: 60' 169.254.169.254/latest/meta-data/` 429s ≥ 3/min · Azure: `curl -m 2 -H 'Metadata: true' 'http://169.254.169.254/metadata/instance?api-version=2021-02-01'` 429s ≥ 3/min · script branches on `/sys/class/dmi/id/sys_vendor` (`Amazon EC2` vs `Microsoft Corporation`) | `iptables -m statistic --mode random` rule on the IMDS IP (same on both) |

### 4.3 Definition of done
- All 7 plugins green on a healthy node, red within 15 s after `make inject-<x>` — **rehearsed on both EKS and kubeadm/Azure test clusters.**
- All 7 NodeConditions visible via `kubectl describe node` on both providers.
- Mapping doc lists ≥3 historical NR incidents (≥1 Azure-side) with the fault class each maps to.
- NPD plugin ConfigMap is **identical** across providers; only `imds.sh` has provider-specific branches and `Makefile` accepts a `CLUSTER=` arg.
- Demo cluster's NPD is **idempotent across redeploys** — wipe ConfigMap + reapply leaves the state clean.

### 5.2 Reconcile flow

The controller has **two informers** doing different jobs:

**Informer A — Node + Event watcher** (read-only). Triggers case creation. Runs predicate filter on the watched-condition set (defined in `--watched-conditions=ConntrackSaturated,FDExhaustion,...` flag). On match, the controller resolves `provider`/`region`/`instanceId` from standard Node labels and writes them into `spec.case` so the agent doesn't have to discover the cloud:

| Field | Source label |
|---|---|
| `provider` | `topology.kubernetes.io/region` prefix + `node.kubernetes.io/instance-type` heuristic, or explicit `cf.newrelic.com/cloud-provider` (preferred — set by argo-webhook) |
| `region`   | `topology.kubernetes.io/region` |
| `instanceId` | AWS: derived from `Node.spec.providerID` (`aws:///<az>/i-…`). Azure: VM name from `providerID` (`azure:///subscriptions/…/virtualMachines/<name>`) |

**Informer B — `NodeHealthDiagnosisAI` reconciler.** Standard controller-runtime reconciler keyed on `nhd` objects. Phase-driven:

```
Reconcile(nhd):
  switch nhd.status.phase:
    case "":
      // we just created it; POST /diagnose; set phase=Diagnosing, AgentInvoked=True
    case "Diagnosing":
      if deadline-exceeded: phase=Failed; emit event; return
      requeue(10s)
    case "Diagnosed":
      // hackathon: skip eval; jump to gate
      if !confidenceGatePass(nhd):
        phase=Acted; action.decision=HumanInLoop; notify "needs review"; return
      cordon(nhd.spec.case.nodeName); phase=Acted; action.decision=Applied
      notify slack+pd; ActionApplied=True
    case "Acted","Failed":
      return  // terminal
```

### 5.3 Confidence gate (binding)

Auto-cordon iff **all** hold:
- `status.diagnosis.confidence >= 0.7`
- `len(unique sources in evidence) >= 2` (sources counted as distinct: `nrql`, `ssh`, `kubectl`, `cloud` (aws/azure), `proc`, `log`)
- `status.diagnosis.recommendation.action ∈ {Cordon, DrainAndCordon}` (NoAction skips cordon entirely)

Below threshold: `action.decision=HumanInLoop`, page CF on-call instead of cordoning. Threshold values exposed as controller flags so we can tune in the demo.

### 6.2 Agent loop wiring

```python
options = ClaudeAgentOptions(
    model="claude-opus-4-7",
    fallback_model="claude-sonnet-4-6",
    system_prompt=load_runbook(),                 # cached on Anthropic side
    permission_mode="default",
    can_use_tool=allowlist_callback,              # see §6.3
    hooks=[("PreToolUse", audit_hook)],
    mcp_servers={
        "node_ops":   nodeops_sdk_server,         # in-proc
        "cloud_info": cloud_info_sdk_server,      # in-proc; dispatches by case.provider
        "nr":         nr_http_server,             # HTTP, existing
    },
    max_turns=case.budgets.maxTurns,
)
async with ClaudeSDKClient(options=options) as client:
    await client.query(build_user_prompt(case))   # injects nodeName, condition, ts, cluster
    async for msg in client.receive_response():
        ...
```

The `emit_report` "tool" is implemented as a **terminal tool**: when the agent calls it, the runner constructs the `NodeHealthDiagnosisAI` object, validates evidence (≥2 distinct sources), POSTs to the apiserver, and ends the loop.

### 6.3 Tool allow-list (binding)

| MCP | Tool | Args (JSON schema, abridged) | Allow rule |
|---|---|---|---|
| `node_ops` | `kubectl_get` | `{kind, name?, namespace?, selector?}` | Read-only verbs only; namespaces in `{kube-system, container-fabric, default}` |
| `node_ops` | `kubectl_describe` | `{kind, name, namespace?}` | Same |
| `node_ops` | `ssh_run` | `{node, cmd}` | `cmd` must match one of: `dmesg --since *`, `journalctl -u kubelet --since *`, `cat /proc/sys/...`, `cat /proc/<pid>/status`, `ss -s`, `df -h`, `df -i`, `nproc`, `uptime` |
| `node_ops` | `read_proc_file` | `{node, path}` | `path` must start with `/proc/sys/` or `/sys/fs/cgroup/` |
| `cloud_info` | `describe_instance_status` | `{instanceId, provider, region}` | Dispatches by `provider`: AWS → `ec2:DescribeInstanceStatus` (read-only IAM); Azure → VM `instanceView` (Reader role on the resource group) |
| `cloud_info` | `describe_health_events` | `{instanceId, provider, region}` | AWS → `health:DescribeEvents`; Azure → Resource Health `availabilityStatuses/current` |
| `cloud_info` | `describe_scheduled_events` | `{instanceId, provider, region}` | AWS → EC2 Scheduled Events; Azure → Scheduled Events metadata API (`/metadata/scheduledevents`) |
| `nr` | `execute_nrql_query`, `analyze_entity_logs`, `analyze_golden_metrics`, `list_change_events`, `get_entity` | as defined by NR MCP | `account_id` forced to `1` (staging) |
| (terminal) | `emit_report` | `{rootCause, rcaCategory, confidence, evidence[], recommendation}` | Validates schema, writes CR, ends loop |

`can_use_tool` rejects anything not in this list. PreToolUse hook records `{caseId, ts, tool, argsHash, allowed, reason}` to `audit/<caseId>.jsonl`, uploaded to S3 at end of case.

### 6.4 System prompt (runbook) — outline

`prompts/runbook.md` content (structure, ~2 KB):
1. **Identity & scope.** "You are NodeMedic. Diagnose worker-node health issues on Kubernetes clusters managed by Container Fabric. Clusters run on **EKS (AWS)** or **kubeadm-managed clusters on Azure**. The case payload tells you which (`provider` field)."
2. **Decision tree** keyed on `trigger.type`: for each NodeCondition (Conntrack, FD, PID, Inode, Disk, DNS, IMDS, Kernel, Kubelet) — what to probe first, what evidence to gather, what's a slam-dunk vs ambiguous. Provider-specific notes called out where they diverge (e.g. IMDS endpoints; Azure CNI vs amazon-vpc-cni for conntrack).
3. **Tool budget** — reminder of `max_turns` and probe-cost guidance.
4. **Evidence-citation requirement.** Every claim in `rootCause` must be supported by at least one `evidence[]` entry; `emit_report` rejects reports with <2 distinct sources.
5. **Confidence calibration.** Examples of `0.9`, `0.7`, `0.4` cases.
6. **Recommendation rubric.** When to choose `Cordon` vs `DrainAndCordon` vs `NoAction`.

The prompt is **prompt-cached** (Anthropic cache_control on the system block) — first invocation pays once, subsequent invocations are cheap. Cache is keyed per process; the agent process is long-lived.
